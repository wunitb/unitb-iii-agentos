## การประเมินสถาปัตยกรรมและความพร้อม

สถาปัตยกรรม worker-per-process บน iii ยังเหมาะให้พัฒนาต่อ. ปัญหาหลักไม่ได้อยู่ที่จำนวน worker แต่เป็น lifecycle ข้าม process, authority ระหว่าง bus/deputy, การทดสอบที่สับสนระหว่าง working trees, และการแยก candidate ออกจาก release ที่ผู้ใช้ดาวน์โหลดจริง.

ขอบเขตความเชื่อถือยังเป็น **single operator บน trusted host**. Default bus mediation, principal propagation และ scoped worker environment เป็น defence in depth; shared `AGENTOS_API_KEY` และ registry-compatible state surface ไม่ได้สร้าง hostile same-UID/multi-tenant sandbox. Process bridge ที่เปิดเองและ manifest-based MCP integrations ยังต้องถือว่าได้รับ executable authority.

การตรวจครั้งนี้รวมการอ่าน handoff/contract/backlog, ตรวจ source ที่เป็นประเด็น, รัน workspace gates ใหม่ และทดสอบ artifact จริง. ไม่ใช่ independent adversarial review ทุก handler และไม่ใช่หลักฐานว่า optional integration ทุกตัวใช้งานกับบริการจริงแล้ว.

## Security blockers ที่ห้ามข้าม

1. **ปิด Node advisory blockers ใน dependency graph แล้ว:** แทน `@opentelemetry/core@1.30.1` ที่ติด `GHSA-8988-4f7v-96qf` ด้วย 2.11.0 และนำ `@opentelemetry/propagator-jaeger@1.30.1` ที่ติด `GHSA-45rx-2jwx-cxfr` ออกจาก graph. Root Bun และ website npm audits ผ่าน โดยไม่ ignore advisory หรือเปลี่ยน iii pin.
2. Migration ใช้ exact overrides ทั้งกลุ่ม OpenTelemetry 2.11.0/0.222.0 พร้อม Bun patch ของ helpers 0.22.1 ทั้ง ESM/CommonJS. ตรวจ clean frozen install และ SDK/OTEL fixture บน Node/Bun แล้ว รวม trace, metric, correlated log และ invalid trace-context rejection. **เป็น compatibility patch ที่ repository ดูแล ไม่ใช่ upstream-supported release.** รอบปิดงานเพิ่มการตรวจ query-back จาก iii 0.22.1 จริงแล้วทั้ง Node/Bun และ ESM/CommonJS; ไม่ใช่แค่ mock receiver. รายละเอียดและข้อจำกัดอยู่ใน migration note; ยังต้องรัน audit แยกจาก `check`.
3. **ปิดแล้วในรอบเตรียมเผยแพร่:** เปิด GitHub private vulnerability reporting และตรวจ repository API ว่า `enabled=true`. ช่องทางรับรายงานอยู่ใน `SECURITY.md`; ไม่สร้างที่อยู่อีเมลขึ้นเอง.
4. **Full cargo-deny ผ่านครบ** หลังถอด dependency `cron@0.12.1` ออกจาก Pulse. ใช้ private UTC due-slot membership แทน future-schedule library โดยคง grammar และตรวจเทียบ legacy parser ก่อนถอด dependency; ไม่เพิ่ม package, exception หรือผ่อน ratchet. Fresh RustSec ไม่พบ known vulnerability และยังมี `fxhash` unmaintained warning ตามเดิม.

Older `init` อาจเคยทิ้ง provider key ใน legacy `$AGENTOS_HOME/config.toml`. ควรตรวจ permissions และย้าย/หมุน key ตามความเสี่ยงของเครื่องนั้น. งานนี้ไม่อ่าน เผยแพร่ หรือลบ credential files ของ operator เพื่อทำให้สถานะดูสะอาด.

## ลำดับงานต่อและเกณฑ์ปล่อย

1. **ปิดแล้ว:** cargo-deny duplicate `nom` และ native-engine OTEL ingestion ของ Node graph ใหม่. ดู closure evidence สำหรับผลของทรีรอบสุดท้าย; ไม่ใช้ผลนี้แทนรายการ product/release ที่แยกอยู่ด้านล่าง.
2. ทำ AgentOS↔memworkr contract และ engine-registry collision coverage; แยก optional capabilities ที่ยังไม่ complete ออกจากสิ่งที่ประกาศว่ารองรับจริง.
3. ตัดสิน/ลงมือ safety-worker wiring และ template lifecycle, ตรวจ remaining suppressions, long-running/fault-injection acceptance และ Pulse UTC scheduling. การวัดหนึ่งนาทีไม่ใช่ endurance/SLA proof.
4. เปิด private disclosure path และทำ real provider/channel acceptance ผ่านช่องทางจัดเก็บ credentials ที่ปลอดภัย ไม่ขอให้ส่ง keys ใน conversation.
5. เมื่อ security gates เขียวและได้รับคำสั่งเผยแพร่ จึง commit → PR → ทุก required CI check ผ่าน/ไม่มี review ค้าง → merge → release/attestation/installer acceptance บนทุก target. **ห้ามใช้ local artifact หรือ base SHA เป็น public release evidence.**

Supervisor นี้แก้ normal Linux lifecycle ของ engine/registry workers ไม่ได้สร้าง OS sandbox, การยกเลิกงานบน server, durable delivery หรือ guarantee ต่อ uncatchable SIGKILL ทุกจังหวะ. macOS foreground lifecycle, hostile same-UID workloads และ live-provider billing/cancellation ยังอยู่นอกหลักฐานที่รับรองครั้งนี้.
